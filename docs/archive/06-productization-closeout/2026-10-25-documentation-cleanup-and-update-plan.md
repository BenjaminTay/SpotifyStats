最终在 reports 下形成一份 `2026-10-25-documentation-cleanup-delivery.md`，包含实际文件处置、旧路径到新路径、规则来源、独立保留项、验证及仓库状态。若实际完成日改变，文件日期采用完成日。执行完成后将本规划归档，更新总表、台账与文档地图；本轮规划状态不提前标记实施完成。

## 四 链接与历史证据保护

- 内容迁移先承接后删减；没有独有信息的重复摘要可以直接缩短，不给每段重复内容另建归档。
- 移动文件与所有仓库内引用在同一批修改；检查标题锚点、反引号路径、HTML 引用、原型内部链接及脚本或测试中的文件路径。
- 对已有外部链接约定或仍需旧深链的页面，保留最小指引或原标题锚点。无已知稳定路径要求时不为每个历史文件建立永久空壳。
- 原始运行收据不改写路径或计时；用旧路径到现位置的映射说明。路径当前不可恢复时如实保留该边界，不通过删除报告掩盖。
- 本地应用、已提交、已推送、已部署、生产专项通过、真实终端和观察完成继续分开记录。归档某份计划不代表其关联产品或观察问题自动关闭。
- OOM、移动端弹层、孤立点、四日期生产应用、数据审核、真实模型和终端、入口及备份观察等独立待办保持各自结论。本任务不重开旧资源矩阵，也不替它们补业务验收。

## 五 验证范围和结束条件

| 改动 | 必要验证 | 通过条件 |
| --- | --- | --- |
| 文字、分类和链接 | 文档审计、差异检查及人工内容核对 | 无断链、失效路径、空指向和范围误述 |
| 标题、迁移和历史分段 | 对受影响路径检查入链与锚点 | 当前入口可达；需要保留的旧深链有承接 |
| 规则提炼 | 将涉及的条款与实际拥有者对照 | 不改变统计语义，不引入新的行为要求 |
| 索引重组 | 一次性比较目录文件集合与索引覆盖 | 保留报告和历史文件均有导航；排除项有具体理由 |
| 工作约定 | 比较两份根文件及领域链接 | AGENTS 与 CLAUDE 完全相同，关键约束保留 |
| 原型迁移或素材删除 | 相对引用检查；移动HTML时做对应静态页面浏览 | 页面可打开、内部资源可用，现有README图片正常 |

文档与路径修改采用以下命令，按阶段需要运行，最终累计版本统一收口；没有新变化时复用已有结果。

```bash
python3 scripts/docs_audit.py --include-archive
git diff --check
```

新增未跟踪 Markdown 也要做空白检查，不能只依赖默认 `git diff --check`。索引覆盖和锚点检查可用一次性只读脚本或人工核对完成，本轮不建设新的文档平台、不默认修改审计脚本或CI。

纯文档阶段不运行应用全量测试、全站浏览器、Phase 5、完整全栈或资源实验。静态原型验收只检查被迁移的原型；若文档路径被现有定向测试直接依赖，修复路径后只运行对应测试。出现业务实现变化需求时拆为独立事项。

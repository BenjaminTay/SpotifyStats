## 1. 目标与完成定义

本轮要让应用启动和长期开着时更轻，同时保留上一轮已取得的页面速度、统计正确性和加载连续性。

交付四项结果：

1. 有可复现的启动、空闲、浏览、导入后重建和长期运行资源基线。
2. 提供适合本机日常使用的轻量启动入口，并量化其相对开发启动方式的收益。
3. 根据实测缩减无收益的预热、重叠计算和大型缓存驻留；对未成立的假设记录证据后跳过改动。
4. 同一数据、同一状态下完成资源前后对照、统计等价和完整本地全栈验收。

本轮不承诺消除所有重建，也不通过少算统计、永久不更新、关闭必要维护或增加页面等待来换取资源数字。

完成判定分开报告：资源专项、功能正确性、本地完整全栈。三项全部通过才能称本轮本地完成；不由此推断生产已经发布。

## 3. 实施范围与工作方式

### 必须覆盖

- 本机开发模式与本机日常使用模式的资源差异。
- 正常 lifespan 启动、必要维护、可选预热和关闭过程。
- 后端大型缓存、重型任务并发与任务完成后的内存保留。
- 浏览器的空闲请求、图表/事件清理、有限预取和长期页面切换。
- 导入后必要维护与已发布结果恢复，不改变导入治理合同。

### 本轮不做

- AI Agent V6、真实模型调用、OAuth、外部元数据请求、UI 改版。
- Redis/Celery、新通用调度平台、数据库替换、统计算法重写或扩大并行 worker 数。
- 为减少占用而改统计口径、近似计算、关闭必要快照发布或恢复 GET 冷建。
- 生产部署、远端容量变更、Docker 常驻策略、域名/Tailscale 变更。
- 擅自停止其他任务或当前用户服务，自动 commit/push，自动改系统电源设置。

用户后续授权整份规划执行后，按 R0—R6 顺序连续推进；阶段间报告结果，不重复索取已经覆盖的实施授权。出现真实数据边界风险、范围外需求或不可满足的外部条件时，停住相关工作并保留证据。

执行优先使用隔离检出，记录基线 HEAD。既有未提交 AI V6 计划及其文档地图入口不归本轮修改。若其他任务也修改 `backend/core/job_queue.py` 等共享文件，应固定各自基线，集成时重验相交行为，不能在持续变化的代码上计时。

## 4. 测量合同与预算

### 4.1 数据、状态与进程隔离

1. 正式库仅通过 SQLite Online Backup 读取到实验副本；运行中的 SQLite sidecar 同样通过一致性备份取得，不直接复制活跃 DB 而漏掉 WAL。
2. 同时复制或重建对应 Home、Yearly、Billboard、Analysis、Community、Archive、Governance 派生结果。固定 source revision，校验快照与主库匹配；不能把不同时间点的副本拼成 exact-ready。
3. Home 文件按现有原子发布方式读取后核对 revision。来源漂移则重取或将该状态标为缺失，不篡改 revision 来通过检查。
4. 在导入应用模块之前重定向全部数据库、快照、锁、队列、日志和导入 staging 路径。导入场景使用实验 raw/account 副本；封面使用隔离副本或本地只读映射。没有路径隔离证据不启动完整 lifespan。
5. 禁止实验调用外部服务。网络类任务记录为受控未执行，不用反复网络失败的噪声冒充业务成本；正常计算维护仍完整运行。
6. 使用现有主机级性能锁，采样前后检查外部测试/构建进程及系统负载。竞争或代码漂移的样本保留并标为污染，不混入正式比较，不强制清理其他进程。
7. 每次启动使用同一冻结基线的独立副本，不能让前一组偷偷替后一组完成预热或发布。记录 PID 与创建时间；预期外重载的 run 判为不可比。
8. 原始数据、快照和性能产物放在本轮临时/证据目录，复用项目数据保护与存储 guard；源码仓库只保存必要的汇总报告。实验结束仅清理本轮拥有的进程和临时文件。

### 4.2 计量口径

| 指标 | 记录方式 |
|---|---|
| 启动时间 | 分别记录进程创建、health 可用、核心页面可用、必要维护完成、可选预热完成；不混成一个“启动成功” |
| CPU | 累计 user+system CPU 秒、窗口时间加权平均和峰值；100% 表示一个逻辑核；首次无差分样本不参与平均 |
| 内存 | 连续 RSS，加关键阶段 macOS physical footprint 与系统报告峰值；记录压缩/换出背景。其他平台单独用其可获得指标，不跨口径作百分比比较 |
| 分组 | 后端、reload 监控、前端服务器、浏览器、探针、构建/测试分开；共享 PID 去重，不简单叠加不同时刻的峰值 |
| 浏览器 | 专用浏览器实例的 CPU/RSS；支持时加 JS heap、DOM/监听器与请求数量。三引擎功能验收，资源主比较固定同一引擎和版本 |
| 缓存 | 命中/未命中、条目数、主要对象估算体积、失效/淘汰原因；不暴露曲名、原始数据或凭据 |
| I/O 与存储 | 可取得的进程读写、DB/WAL/sidecar 增量；不支持的计数记 null，不记 0 |
| 功耗 | CPU 秒、唤醒和后台活动作为资源代理指标；只有取得实际能量测量时才报告瓦数或焦耳 |

复用 `scripts/runtime_resource_probe.py` 与现有性能 schema。高频采样原则上 0.5—1 秒；昂贵内存诊断和分配 profile 只做独立归因运行，不能污染用于前后对照的计时。完整窗口开始于目标进程创建之前，覆盖停止前的稳定段。

现有 `scripts/performance_server.py` 关闭 warmup、Search/L3 启动开关，并设置 `lifespan="off"`，只能作为既有独立读取探针。R0 应增加明确的完整生命周期测量入口，默认保持旧探针语义，不能直接把旧工具的结果命名为启动基线。

### 4.3 基线状态与对照矩阵

分别冻结三种数据状态：E 为配置与快照均 exact-ready；M 为必要快照缺失；D 为实验导入/合法配置改变后的待维护状态。E 的轻量启动不能代替 M/D 的维护验收。

E 状态下执行以下启动对照，每组至少 3 次独立进程运行；顺序交错，以减小系统页缓存和温度变化影响。不清空系统页缓存，不声称测到磁盘冷启动。

| 组 | 后端 | 前端 | 预热 | 归因 |
|---|---|---|---|---|
| A | 现有开发 reload | 开发服务 | 当前行为 | 用户当前启动方式基线 |
| B | 无 reload，单服务进程 | 开发服务 | 与 A 相同 | A/B 只比较文件监控成本 |
| C | 同 B | 开发服务 | 仅关闭可选启动预热 | B/C 比较预热，保留正常维护队列 |
| D | 同 B | 正式构建的本机静态入口 | 与 B 相同 | B/D 比较前端运行方式 |
| F | 最终日常运行方式 | 同 D | 最终策略 | F/D 比较业务资源优化；F/A 报告用户总收益 |

先完成前端构建再计时，构建开销单列。不能将 F/A 的全部收益宣传为算法优化。D 必须使用用户实际可直接访问的 `/api`、`/covers` 和深链，不借助浏览器测试代理补齐才能运行。

各组启动达到业务稳定后继续采集 5 分钟空闲；若必要任务未完成则继续记录为维护状态，超出 R0 预设超时保留失败，不用固定等待掩盖未完成。

### 4.4 预定验收目标

以下是本轮的工程目标，不是已实现成果。R0 固定数据规模、具体页面、样本、同口径基线与门槛后再进入优化。若目标与已证实的必要工作冲突，先交付差距和原因；不得在看到优化失败后降低门槛来宣告通过。

| 项目 | 目标 |
|---|---|
| 正确性 | 次数/时长、L2/L3、排序、revision、状态和来源合同保持；只允许排除已确认的非语义时间字段 |
| 日常模式空闲 | 无重建、无活跃交互时，后端加本机静态服务 5 分钟平均 CPU ≤1%（单核口径）；浏览器另列，不隐藏其开销 |
| E 状态启动 | 最终策略相对 D 的启动至稳定 CPU 秒、后端内存峰值目标各降低 ≥30%；若 D 已分别达到 ≤5 CPU 秒、峰值 ≤768 MiB，可用绝对目标达标停止，不为百分比强改 |
| E 状态稳定内存 | 后端 footprint 目标 ≤768 MiB；压缩/换出不能作为释放收益 |
| M/D 重建 | 已有单项资源门槛不放宽；整段后端峰值目标 ≤1.5 GiB，并记录每类任务与排队时间。该新预算不替代上一轮任务级 RSS 门槛 |
| 页面速度 | 既有路由绝对预算继续通过；同状态核心 ready 中位数相对 D 的退步不得超过 `max(100ms, 基线×10%)`；无结果/错误不算 ready |
| 重建耗时 | 同状态必要维护完成时间相对 D 的退步不得超过 `max(1s, 基线×10%)`；不能靠串行后无限排队只压低峰值 |
| 长期内存 | 同一有限交互集合重复 3 轮，每轮 20 分钟；后端与浏览器分别比较第 2、3 轮结束后同样 5 分钟稳定段，占用增长 ≤`max(50MiB, 第2轮×10%)`；同时核查条目/对象是否无界积累 |
| 空闲请求 | 页面进入 ready 后没有无必要的准备/更新轮询；必要 LKG 更新可以继续，但结束后停止，隐藏页不做高频无效轮询 |

长期测试分别覆盖重复访问同一集合和扩大到超过目标缓存容量的合法筛选集合。第 3 轮增量不大只证明本次窗口受控，不等于证明永久无泄漏；持续增加的对象即使暂未超数字门槛也须定位。

三次样本报告 raw/min/median/max，不报告“稳定 P95”。绝对门槛按其指定窗口检查，不丢弃最大样本；只有有证据的外部污染才能排除。

## 5. 分阶段实施

### R0：安全测量入口、基线与归因

**工作**

1. 固定隔离检出、数据与 E/M/D 状态、基线服务配置，建立样本清单和上述门槛。
2. 补齐正常生命周期入口、进程创建前采样、PID 变化检测、CPU 累计秒和 macOS 内存口径；保持旧工具兼容。
3. 记录启动步骤、任务队列、缓存填充的开始/结束和关键阶段内存，不新增常驻监控服务。
4. 完成 A/B/C/D 对照、基线典型页面和一次 60 分钟有限交互序列；M/D 单独完成必要维护归因。
5. 对峰值来源按导入/迁移与身份准备、播放事实、预热、后台重建、年度结果、浏览器分组。若 RSS 与 footprint 差异较大，进一步核对对象保留与分配器缓存，不据此直接认定泄漏。

**交付**：可运行的隔离测量入口、原始数据、基线表、主要开销排序、R2—R5 的具体修改候选与无须修改项。

**门禁**：全路径隔离、正常 lifespan、快照一致性与采样有效；至少三次可比启动；竞争样本单列。基线不成立时不进入依赖它的优化，其他不依赖计时的合同检查可继续。

### R1：本机日常轻量启动

**工作**

- 提供一个本机日常入口：后端不启用 reload，使用前端已有正式构建。开发入口继续保留。
- 复用现有运行组件。优先检查现有 preview/静态服务能力、API 与封面转发、SPA 深链和 CORS；必要时做最小配置，不把仅测试用 preview 宣传为公网生产服务器。
- 构建过期时给出明确更新方式，或仅在源码/依赖变化后重建；避免每次启动都构建前端。
- 端口冲突明确报错，不终止其他监听进程；绑定 loopback，正确传播退出信号，只关闭自身子进程。
- 首次启动、重复启动、已有构建、构建过期、终端关闭和异常退出分别验证。

**可能触及**：根 README、`frontend/package.json`、`frontend/vite.config.ts`、一个最小启动脚本。具体文件由 R0/R1 证据确定。

**交付**：可直接使用的日常启动入口与说明、A/B/D 资源对照。

**门禁**：真实浏览器直接访问 API、封面及深链成功；无后台遗留；开发入口不回归。此阶段收益归为运行方式改进。

### R2：缩减启动预热并保留必要维护

**工作**

1. 列出每项启动工作属于必要恢复、缺失结果发布还是可选进程内预热。
2. 精确结果有效时跳过无收益的全量事实加载，不反复计算只为填满内存缓存。
3. 保留导入恢复屏障、身份与署名一致性、缺失快照准备和 source fence；数据不一致时不能用旧快照伪装 ready。
4. 对非首屏的可选预热按测量结果取消或延后。不能把原本无人访问也必须完成的发布改成永久等待用户点击。
5. 正常队列与预热共用必要的重型计算约束；避免两套调度重复执行同一 key/revision。复用已有队列/singleflight，不另造调度平台。
6. 本轮触及的环境开关统一经 `backend/core/config.py`，保留可测试的旧策略回退；不扩展为全仓配置重构。

**可能触及**：`backend/main.py`、`backend/core/warmup.py`、`backend/core/config.py`、对应 snapshot service 的启动判断。

**交付**：启动任务清单、最小预热策略、E/M/D 前后对照、旧/新策略切换方法。

**门禁**：E 快速恢复；M 能完成必要发布；D 完成正确新代；失败保留旧代；首次访问满足页面预算；公开 GET 零构建、零写入、零排队。

### R3：大型缓存与计算对象生命周期

**工作**

1. 优先处理 R0 证实的最大保留对象，区分 DataFrame、派生结果、深复制、仍被引用对象和分配器保留。
2. 复用已有 `invalidate_except()` 和单次构建上下文；在任务完成/失败后释放不再需要的重型事实，保留小型高命中结果及并发消费者仍在使用的对象。
3. 根据对象大小和命中收益缩减目标 LRU 容量或采用局部按字节约束。估算放在构建/发布时，避免每个 GET 遍历整份对象算大小。
4. 若 TTL 的实际可达键空间造成积累，为目标缓存增加容量和有界过期回收。失效、更新和并发语义保持一致，不增加全局高频清理线程。
5. 如果释放 Python 引用后内存仍高，先用归因证据判断；不默认强制每请求 GC、定时重启或跨进程化。确需独立进程架构时作为超出本轮的独立提案，不顺手实施。

**可能触及**：`backend/core/cache.py`、`backend/core/cache_manager.py`、`backend/core/db.py`、被证明占用高的具体 builder/cache。

**交付**：主要缓存容量及用途表、内存保留变化、命中率/重算代价对照。

**门禁**：容量和引用保持有界，统计全字段等价，并发安全，页面与重建时间不突破预算；不得通过反复全清缓存制造冷建抖动。已经满足预算且未发现积累的缓存不改。

### R4：重型任务协调与空闲唤醒

**工作**

- 保持必要恢复优先级、同 key 去重与网络任务分离；串行限制检查嵌套调用，避免重入死锁和业务饥饿。
- 对已测得有意义的空闲唤醒，改为可靠的事件/条件等待或有界退避；入队、延迟重试、停止都能立即唤醒，防止 clear/wait 竞态丢通知。

**可能触及**：`backend/core/job_queue.py`、R2 的预热调度边界、对应队列与启动测试。

**交付**：重型任务时间线、同时运行数量、排队时间、空闲 CPU/唤醒对照。

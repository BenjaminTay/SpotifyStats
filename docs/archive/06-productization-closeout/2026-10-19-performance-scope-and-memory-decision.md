## 2. 为什么原流程变重，以及本次取舍

原问题链从慢请求扩展到宽表复制、缓存所有权、启动维护和分配器；真实OOM说明稳定性值得处理。但完整资源矩阵又叠加了镜像搬运、七库准备、工具校验、学校共享宿主保护与恢复。曾出现路径404、成品503、数据库身份变化引发重建、采样器自占内存、回传文件数和清理顺序误报。部分工作是在修验证基础设施，没有直接改善产品。

- 取消默认必须跑完114窗口、两版各90浏览器、每项三次启动及独立90分钟压力流程的路线。它们保留为历史方案，只有具体回归风险需要时才选取相关场景。
- 原热100ms、单请求64MiB、峰值/驻留下降50%、固定8MiB波动容差保留为历史比较指标，不再共同决定本任务能否交付。达不到旧指标不改写为旧验收通过；新验收按下文实际容量和体验评估。
- 保留统计事实正确、正式数据完整、现有公开读取边界与必要发布回退。减少覆盖范围和重复次数，不通过删除失败断言、把错误当成功来节省测试。
- 每轮实验必须对应一个待决定的问题。已经有证据的结论复用；同一补丁、数据和有效环境不变时不为获得更多绿标重复测量。

学校机10-17快照为4核/7.755GiB且运行16个其他服务，也不是专用测试机。生产机不是禁止测试的环境；区别在于被动观察、正常请求与主动资源压力。容器隔离不能消除宿主CPU和磁盘竞争。当前生产可用余量尚未重测，不能在规划中直接断言可并行运行副本。

Docker文档说明跨架构仿真会增加计算开销，见[多平台说明](https://docs.docker.com/build/building/multi-platform/)。学校机选择的实际记录见[学校准入报告](../../reports/2026-10-17-school-native-resource-admission.md)；本机ARM引擎运行amd64镜像的现状已在详情会话中核对，其正在整理的对象归因报告由该会话独立交付。

## 4. 已执行的精简交付路径（历史步骤）

以下为制定计划时的步骤记录：第1–4步已完成，第5步发布已完成，仅正常使用观察尚未结束；当前不重跑这些步骤或追加实验。

1. **收尾正在运行的归因，先给决定。** 复用详情会话已获授权的当前窗口及时间上限；现有结果约41.52MiB可达缓存对象只是中间证据。取得本窗清理/GC/trim与自然读取结果后，给出“业务持有增长 / 分配器保留 / 尚不能区分”的结论和采取或不采取修复的理由。本计划不追加窗口；已按用户后续明确要求向详情会话发送收尾后切换新范围的指令，不重启或重跑当前实验。
2. **核实实际需求与生产容量。** 优先读取现有日志和资源记录，核对现版本、Backend限额、宿主可用内存、维护竞争与近期OOM/重启。必要时只增加一次10–15分钟、单客户端、最多12次代表性正常请求观察，不启动新压力测试。此阶段先固定实际内存预算与停止线，再执行后续候选验证；本次规划没有执行这些生产操作。
3. **选择最小可交付补丁。** 复用唯一研发树，审阅累计候选，按“解决哪个实际问题、有什么证据、引入多少发布成本”决定采用或暂存。schema91发布结构候选不因已投入时间就必须打包交付；如果采用，正常启动、失效、迁移与回退必须覆盖。未解释的每一块arena、每个小幅收益不作为继续开发的理由。
4. **只验证受影响链。** 默认一次基线/候选对照，观察同一组歌曲/专辑/艺人代表请求的统计、内存和耗时；测量段以20–30分钟为计划范围，准备与清理成本另计入执行前总预算。已有可比较原生基线直接复用。改了淘汰逻辑才让该缓存真实淘汰，改了维护路径才做相应维护。出现新失败才补一轮定向修复与复验；仍不明确则交付取舍决定，不自动续跑矩阵。
5. **固定版本交付与自然使用观察。** 当前累计补丁跨统计/发布模块，最终采用范围冻结后做一次必要整体验证；相同业务源码的有效结果可复用。随后走现有CI、备份与发布回退流程。上线后用既有日志和正常使用观察约1–3天，不连续注入压力流量；无实际使用的时间不算使用验证。功能已交付与资源观察中分开记录。

## 5. 精简后的验收标准

- **数据正确：** 受影响歌曲/专辑/艺人和实际改动涉及的合并、署名、过滤边界，次数、时长、排名与对照一致；正式原始表不被优化改写。已有对账直接复用，发布结构改动另验持久化和失效。
- **体验达标：** 保持已交付的点击核心2秒、默认可见内容2.5秒、直达核心3秒体验目标及正确错误状态。只跑受影响交互和代表视口；没有前端/共享交互变化不重跑三浏览器全站矩阵。接口100ms用于定位，不独立驱动新架构改造。
- **容量够用：** 在所选原生环境和实际部署预算内，正常启动、代表读取及本轮涉及的必要维护不触发OOM或意外重启，并留出已核实的宿主余量。先读现状再定数值，不沿用学校2GiB限额冒充生产预算。
- **增长可控：** 相同工作集重复使用后占用趋稳或增长有明确上限、能在实际容量内运行。RSS高于启动值或释放对象后未立即下降本身不判失败；如果持续增长或逼近停止线，问题仍开放，需修复或明确容量/运行策略。短窗口不能证明所有未来负载，后续自然使用只补这一缺口。
- **结项：** 采用补丁已交付，代表使用与相关维护有上述证据，观察中无归因于本链的新OOM/重启，关闭本稳定性任务；未采用优化保留为候选，不作为结项欠账。只有部分证据则说明具体未满足项，不列旧矩阵剩余数。

## 6. 什么时候需要更多测试

| 本次变化 | 足够的默认验证 | 扩大条件 |
| --- | --- | --- |
| 规划、说明、状态更新 | 文档审计、diff检查 | 链接或格式失败时修正；不运行应用测试 |
| 局部缓存/生命周期修复 | 对应回归、受影响真实结果对账、一组资源对照 | 出现统计差异、资源回归或影响共享调用者 |
| 全局统计、schema、发布或启动改动 | 对应迁移/失效/正常启动测试；最终固定累计版本一次整体验证 | 新代码改动影响已验范围；单纯补报告不重跑 |
| 正式发布 | 现有必需CI、备份/回退、健康与受影响页面验收 | 新发布故障或事实变化；不把完整压力实验放进生产 |

现有CI与部署必需检查不在本次修改；局部验证仍如实标明范围，不能宣称全栈Pass。保护数据与必要回退保留，临时运行材料只保留一套必要原始证据和可用恢复入口，不继续开发通用审计/恢复平台。

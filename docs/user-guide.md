# 使用指南

本指南面向在自己设备上使用 SpotifyStats 的用户，介绍安装、数据导入、日常查看和可选服务。修改程序请阅读[开发指南](../CONTRIBUTING.md)。

## 安装与首次启动

### 准备环境

安装 Python 3.9 或更新版本、Node.js 22.x（最低 22.13.0，建议安装 22.x 最新维护版本），并准备常用的现代浏览器。下面的终端示例使用 macOS／Linux 的命令语法。

下载并解压本项目，在终端进入项目根目录。依次执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd frontend
npm ci --legacy-peer-deps
cd ..
```

首次启动执行：

```bash
python3 scripts/start_daily.py --build
```

终端保持运行，在浏览器打开 <http://127.0.0.1:4173>。这个地址用于当前设备上的日常查看。关闭时在启动终端按 `Ctrl-C`。

首次打开还没有个人数据，需要继续完成下面的导入步骤。

### 准备 Spotify 数据

在 [Spotify 隐私设置](https://www.spotify.com/account/privacy/) 请求 **Extended Streaming History** 和 **Account Data**。下载后先解压，保留原始导出文件。

| 数据包 | 用于什么 | 如何准备 |
| --- | --- | --- |
| Extended Streaming History | 播放次数、时长、排行、年度总结与个人榜单 | 在设置页选择并上传解压后的播放记录 JSON 文件。 |
| Account Data | 收藏、歌单、搜索记录、播客等音乐档案 | 将解压后的账号 JSON 放入运行设备的 `data/account/`，再在设置页单独导入账号资料。 |

播放历史与账号资料是两类数据，按各自入口导入。文件名和字段需要进一步排查时，可查阅[数据格式参考](../data/README.md)。

## 导入并检查数据

1. 打开「设置 → 数据导入」。
2. 为播放历史创建导入批次，选择 JSON 文件并完成上传，再运行导入前检查。
3. 阅读检查结果；需要确认替换或历史变化时，先核对输入文件，再确认执行。
4. 等待导入和后续处理，查看阶段状态、数据健康和报告。
5. 如需音乐档案内容，放好账号 JSON 后点击「导入账号资料」。

启动应用不会自动导入导出文件。首次处理或新增较多记录时，部分统计、封面和榜单需要等待；数据尚未准备好时，不应把页面暂时没有结果理解为零播放。

某个处理阶段失败时，先查看该阶段的提示和报告，按页面提供的重试入口处理。不要仅因封面或外部资料失败就反复重新导入同一批播放记录。

## 日常启动与更新

完成首次安装和处理后，在项目根目录运行：

```bash
python3 scripts/start_daily.py
```

然后访问 <http://127.0.0.1:4173>。终端关闭后服务也会结束，下次查看时重新启动即可。

### 更新项目

按下面顺序更新，先核对本机版本是否仍满足[准备环境](#准备环境)的要求。依赖安装按文件是否变化选择执行；`--build` 只负责构建和启动，不会自动安装或更新依赖。

1. 在旧入口的启动终端按 `Ctrl-C`，等待它退出，再更新项目文件。保留自己的 `.env` 和 `data/`，不要用新下载的空目录覆盖个人资料。
2. 若根目录的 `requirements.txt` 或它引用的任意依赖清单发生变化，在项目根目录更新 Python 依赖。当前子清单为 `requirements-analytics.txt`、`requirements-api.txt`、`requirements-features.txt` 和 `requirements-search.txt`。不确定哪些清单变化时，也执行下面的命令；统一从根清单安装，它会包含所引用的子清单：

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

3. 若 `frontend/package.json` 或 `frontend/package-lock.json` 发生变化，从项目根目录更新前端依赖：

```bash
cd frontend
npm ci --legacy-peer-deps
cd ..
```

4. 回到项目根目录，重新构建并启动：

```bash
python3 scripts/start_daily.py --build
```

5. 在浏览器重新打开 <http://127.0.0.1:4173>。若更新后提示缺少模块，先核对上面的依赖安装步骤；若提示端口被占用，检查旧入口是否已经退出，不要结束其他无关服务。

### 检查启动条件

在入口未运行时，只检查构建与端口是否可以启动：

```bash
python3 scripts/start_daily.py --check
```

构建过期时，按提示运行 `--build`；端口被占用时，先检查已有启动终端。`--check` 不会关闭已经运行的服务。

## 浏览自己的音乐记录

- **首页**：先看最近的听歌动态和个人头版，再进入详细内容。
- **播放分析**：选择时间范围，查看播放统计、排行、年度总结和播放记录。
- **个人 Billboard**：查看自己的周榜、年榜、榜单记录及对决。
- **音乐档案**：浏览已导入的收藏、歌单和其他账号资料。
- **音乐查找与详情**：搜索歌曲、专辑或艺人，查看自己的收听与榜单表现。

播放次数和收听时长反映不同侧面；歌曲版本、专辑归属和合作艺人也会影响统计归类。需要理解具体结果时，查阅[统计口径参考](reference/playback-stats-rules.md)，调整设置后留意相关处理是否已经完成。

## 可选的音乐资料与 AI 服务

### Spotify 连接

Spotify凭据用于补充音乐资料；连接个人账号后还可按页面提供的功能同步收藏信息。播放历史JSON仍需从数据导入入口导入。

授权前先确认 Spotify 应用和账号具备访问条件：

- 新建应用默认处于开发模式（Development mode），应用所有者必须拥有有效的 Spotify Premium 订阅，开发模式应用才能正常使用。
- 在开发者控制台的应用设置 → Users Management 中核对实际登录账号的访问权限。若使用非应用所有者账号，先由所有者点击 Add new user，填写该账号的姓名和 Spotify 邮箱，将其加入允许名单，再用该账号授权。
- 未加入允许名单的账号可能完成登录，但后续 API 请求会返回 403。遇到这种情况，先核对账号和允许名单；本地播放历史 JSON 的导入与统计不受该访问条件限制。

以上前提依据 [Spotify 开发模式与用户访问规则](https://developer.spotify.com/documentation/web-api/concepts/quota-modes)（核对于2026-10-26）；平台限制可能变化，以官方说明及应用控制台为准。

本指南的日常入口是 <http://127.0.0.1:4173>。需要连接个人账号时，按以下步骤配置：

1. 在 [Spotify开发者控制台](https://developer.spotify.com/dashboard) 创建或打开自己使用的应用，取得 Client ID 和 Client Secret。在应用设置的 Redirect URIs 中添加并保存下面的完整地址：

```text
http://127.0.0.1:4173/api/spotify/auth/callback
```

2. 在项目根目录创建或编辑自己的 `.env`。没有该文件时可参考 [`.env.example`](../.env.example) 新建；已有配置应保留。填写自己的 `SPOTIFY_CLIENT_ID`、`SPOTIFY_CLIENT_SECRET`，并显式设置回调地址：

```dotenv
SPOTIFY_REDIRECT_URI=http://127.0.0.1:4173/api/spotify/auth/callback
```

3. 保持平台登记与 `.env` 中的协议、主机、端口和路径一致；本机配置使用 `127.0.0.1`，不要把它改成 `localhost`。不要直接沿用示例中的旧开发端口5173。若自行更改了访问端口，或使用维护者配置的远程入口，回调地址也须与实际入口匹配；远程入口使用HTTPS。具体要求见 [Spotify回调地址规则](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri)。
4. 修改 `.env` 后，在原启动终端按 `Ctrl-C` 停止入口，再在项目根目录运行 `python3 scripts/start_daily.py`。重新打开 <http://127.0.0.1:4173>，进入「设置 → Spotify 连接」，点击「连接 Spotify」并完成授权。成功后应回到设置页并显示连接成功。

没有配置或外部服务不可用时，可能缺少封面、元数据，或有部分结果暂未准备好。授权后打不开回调页时，先核对上述地址与端口，再确认修改配置后已经重启；播放历史文件与在线资料应分别核对。

### AI 洞察

在设置页的「LLM 配置」中选择服务、模型和服务地址，填写对应的 API Key 并保存。问答需要所选服务与模型支持工具调用。

进入 AI 洞察后，可主动提问或生成报告。仅打开页面不会自动生成新报告。年度叙事可以在生成过程中逐章阅读已经完成审核的内容；遇到失败时按页面提示处理。

AI 服务可能收费，且会接收回答或报告所需的数据。请按自己的隐私偏好配置；基础播放分析与确定性年度总结不依赖 AI 生成。

## 在手机或其他设备上查看

界面适配手机浏览，但当前设备的 `127.0.0.1` 地址不能直接在另一台设备上打开。跨设备查看需要由运行设备的维护者配置访问入口。

自建远程入口、设置访问密码或公开分享时，请阅读[部署与运维手册](../deploy/production/README.md)。分享页面前确认数据展示范围；不要把个人账号资料、密钥或本地数据目录直接公开。数据导入和系统维护建议在桌面端完成。

## 常见问题

| 遇到的问题 | 可以先做什么 |
| --- | --- |
| 首页没有我的记录 | 确认播放历史已经在设置页导入，并查看后续处理是否完成。 |
| 音乐档案没有收藏或歌单 | 确认 Account Data 已放在运行设备的账号资料目录，并单独完成导入。 |
| 封面缺失或部分结果尚未准备好 | 检查音乐资料连接与处理阶段，查看具体提示；不要把暂缺结果当作零播放。 |
| 更新后提示缺少模块或需要重新构建 | 按[更新项目](#更新项目)先停止旧入口、按需安装依赖，再构建并启动。 |
| 提示端口被占用 | 检查是否已经启动过应用；先使用现有窗口，或关闭自己先前启动的进程。 |
| Spotify授权后无法返回 | 检查平台登记与[Spotify连接配置](#spotify-连接)的回调地址、端口是否一致，修改配置后重新启动。 |
| Spotify登录成功但同步返回403 | 按[Spotify连接前提](#spotify-连接)检查实际账号的允许名单及应用所有者的Premium状态。 |
| AI 无法生成 | 检查模型、服务地址、API Key、额度和工具调用支持，按页面错误提示处理。 |
| 需要备份或移动到其他设备 | 由维护者按[备份与恢复说明](../deploy/production/README.md#发布回滚与-github-actions)操作，保留完整数据与配置。 |

需要维护者协助时，提供操作步骤、页面提示和相应报告；分享前移除密钥及不希望公开的个人听歌信息。[问题台账](issues/README.md)保存已知问题与证据，当前处理进度见[开发状态](DEVELOPMENT_STATUS.md)。

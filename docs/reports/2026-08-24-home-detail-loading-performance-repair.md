# 首页与音乐详情加载性能修复交付报告

> 状态：Pass
> 证据日期：2026-08-24
> 范围：本地代码、真实本地数据库、独立冷启动后端、自动化测试与本地真实浏览器；不代表生产环境已经发布或复验。

## 结论

本轮完整覆盖了首页无内存缓存时重新加载慢、歌曲/专辑/艺人详情偶发慢、详情播放统计冷加载慢，以及专辑/艺人子榜成绩被错误显示为“未入榜”四类问题。

修复后的独立冷进程探针全部通过：首页在“进程内存冷、已有有效磁盘快照”时第一次请求 275.61ms、热请求 P50 47.39ms；歌曲、专辑、艺人摘要第一次请求分别为 122.08ms、57.40ms、14.34ms；三类基础播放统计第一次请求分别为 203.39ms、284.01ms、993.85ms。探针门禁为摘要 500ms、基础统计冷请求 1,500ms、统计热请求 150ms、首页热请求 80ms。连磁盘快照也不存在的首次首页事实构建约 1.95–2.35 秒、峰值内存约 404–409MiB；相比原约 7.7 秒、855MiB 已明显降低，完成后会持久化供后续进程复用。

## 根因与修复

### 首页

- 原冷构建会读取宽播放帧、完整艺人署名 fan-out，并在首页路径中重复承担不必要的 lifetime 工作，真实库直接构建曾约 7.7 秒、峰值内存约 855MiB。
- 首页改用明确的轻量列集合；艺人 fan-out 只覆盖最近两个四周窗口；长期不同艺人数改读有效署名表；不需要时长的专辑计数不再构建时长切片。
- 首页响应增加 revision/filter 精确键的原子 JSON 快照与语义 Last Known Good。精确快照命中时跨进程直接返回；revision 变化且存在 LKG 时先返回 `warming` 旧事实并在后台重建，避免导航请求等待完整计算。
- 预热顺序改为首页优先，年度与其他重型分析延后；后台 CPU 重型维护任务串行，避免导入后多个全库任务同时争抢 CPU 和内存。

### 详情首屏

- 旧 `summary` 实际仍会先构建完整 Billboard 详情，只在序列化时裁剪，所以偶发耗时仍与完整详情相同。
- 新摘要直接读取当前精确音乐查找 snapshot 和轻量元数据 SQL，不再计算周历史、成员榜和完整 Billboard 详情；找不到兼容精确 snapshot 或使用自定义年份时才安全回退旧 builder。
- 完整详情、overview、tracks、albums、project 仍保留原有事实和兼容接口；可重复探针验证摘要共同字段与完整详情一致，各子视图可无损重组完整响应。

### 播放统计与排名

- 原实体统计为计算全局排名，会先加载全库播放帧；艺人还会 fan-out 全库署名，导致冷请求约 2–3.6 秒。
- 首屏现在请求 `include_rank_context=false` 的实体基础统计，只加载目标曲目以及每段目标播放前一条有效上下文，保留连续播放重建边界；全局排名随后通过独立 Query 后台加载。
- 不能只在 SQL 中筛目标曲目后直接合并，否则被其他歌曲隔开的同曲播放会被错误合并。本轮的“一行左上下文”设计在降低读取量的同时保持逻辑事件完全一致。
- 歌曲、专辑、艺人的快速路径与完整路径在周期、实体、首次/最近播放、汇总、每日指标、时钟、趋势、累计趋势、星期、月份和年份分布上逐字段完全一致；仅排名、Top 250 和最近全局上下文按设计延后。
- 统计与年度构建增加 revision-keyed 响应缓存；`singleflight` 从函数级全局锁改为按参数键去重，不同实体不再互相串行。

### 子榜成绩错误空态

- 轻量摘要按设计把 `track_chart_status` / `album_chart_status` 设为未知，但前端页签错误地继续使用摘要状态判断页签结果，因此真实页签已经返回数据时仍显示“暂无入榜”。
- 单曲成绩和专辑成绩现在只使用各自页签响应中的状态与数据；加载完成前显示骨架，确认未入榜后才显示空态。Phone 摘要未知时显示“进入查看”，不再把缺失状态解释成“暂无”。
- 真实库复核：Midnights 专辑单曲成绩 23 首；Taylor Swift 艺人单曲成绩 301 首、专辑成绩 18 张，均已在浏览器正确显示。

## 保留边界

- 全局排名仍需要完整库级上下文，但已移出可见首屏；第一次打开后会在后台计算并被 revision-keyed cache 复用。
- 性能表中的首页第一次请求是“新进程且内存冷、但已有有效磁盘快照”，不是删除所有磁盘快照后的首次构建；后者实测约 1.95–2.35 秒。
- 首页 LKG 的 `warming` 状态明确表示旧 snapshot 正在后台更新，不会伪装成当前 revision 已完全 ready。
- 本轮没有修改播放次数、时长切片、专辑项目或艺人署名的统计规则。
- 生产部署、真实公网网络时延和生产进程重启后的性能不在本轮范围，需要在发布 commit SHA 后另行复验。
